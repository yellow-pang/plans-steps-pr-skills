# Reviewing Development Work

검토 대상과 원래 요구를 먼저 구분한다. 분석은 사실·가정과 영향 종료 근거, Plan은 방향·계약·검증, 구현은 실제 diff/runtime·영향·검증을 확인한다. 문서나 작성자의 설명만으로 현재 구현의 정합성을 확정하지 않는다. 대상에 맞는 관점만 [검토 관점](references/review-lenses.md)에서 읽는다.

중요 발견을 영향·위치·근거·필요한 조치와 함께 우선순위에 맞게 보고한다. 확인하지 못한 것은 한계로 적는다. 발견이 없으면 확인 범위를 밝힌다. 같은 작성자의 자기 점검을 독립 검증으로 표현하지 않는다.

검토만 요청됐다면 발견 보고에서 끝난다. “검토하고 수정”을 요청받았다면 발견을 현재 구현 작업에 연결한다. 별도 모델·세션·승인 문자열이나 모든 작업의 Review 단계를 강제하지 않는다. 검토 자체가 코드 수정이나 Git 실행 권한을 부여하지 않는다.
