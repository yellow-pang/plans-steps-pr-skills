# Preparing Commit

## 핵심 원칙

현재 커밋 대상을 실제 diff와 안전하게 확인한 관련 untracked 파일을 기준으로 판단한 뒤 Conventional Commit 메시지 후보만 작성합니다. 분석만 수행했거나 실제 변경이 없으면 메시지를 생성하지 않습니다.

## 상태와 변경 확인

1. 적용되는 저장소 지침과 커밋 관례를 확인합니다.
2. `git status --short`로 staged, unstaged, untracked 변경을 구분합니다.
3. 파일명과 유형으로 비밀정보 가능 경로를 먼저 선별하고, 해당 내용이나 값은 diff로 출력하지 않습니다.
4. 나머지 staged 변경은 `git diff --cached`, unstaged 변경은 `git diff`로 확인합니다.
5. staged 변경이 있으면 해당 diff를 현재 커밋 메시지의 주 기준으로 사용하고, unstaged 변경은 포함되지 않은 변경으로 별도 보고합니다.
6. staged 변경이 없으면 unstaged 변경을 후보로 분석하되 아직 staging되지 않았음을 명시합니다.

같은 파일에 staged와 unstaged 변경이 함께 있으면 파일명이 아니라 각 diff의 실제 변경 범위를 기준으로 판단합니다.

## Untracked 파일

- 먼저 파일명, 경로, 유형, 크기와 ignore 상태를 확인합니다. 비밀정보 가능성이 낮을 때만 필요한 최소 범위의 내용을 읽습니다.
- 사용자 요청, 변경된 코드의 참조 관계 또는 대응하는 테스트처럼 근거가 있어 현재 작업에서 새로 생성됐거나 명확히 관련된 파일만 후보에 반영합니다.
- 기존 사용자 파일이거나 관련성이 불명확하면 자동 반영하지 않고 별도 보고합니다.
- untracked 파일을 자동 staging하지 않습니다.

## 비밀정보 보호

staged, unstaged, untracked 여부와 관계없이 환경설정, 키, 인증서, credential, 토큰 등 비밀정보 가능 파일이나 값은 내용을 출력하지 않습니다. 커밋 후보에 민감정보가 포함될 가능성과 확인이 필요한 경로만 보고합니다.

## 커밋 분리와 prefix

서로 독립적인 기능, 수정, 리팩터링, 문서, 테스트, 빌드 또는 CI 변경을 하나로 합치지 않습니다. 하나의 목적과 제목으로 설명하기 어렵거나 독립적으로 되돌릴 수 있으면 커밋 분리를 제안하고, 각 후보의 포함 범위와 메시지를 따로 제시합니다.

서로 다른 목적이 이미 함께 staged되어 있으면 현재 상태의 단일 커밋 메시지를 만들지 않습니다. 제안한 분리안과 실제 커밋 대상을 맞추려면 사용자가 staging 구성을 조정해야 한다고 안내합니다.

기본 prefix는 `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `style`, `ci`, `build`입니다. scope는 저장소 관례가 있거나 영역을 명확히 할 때만 제안합니다.

## 메시지 형식

제목과 필요한 경우의 본문은 기본적으로 한글로 작성합니다.

```text
<prefix>: <한글 제목>

- 실제 변경 목적과 주요 결과
- 메시지 이해에 필요한 주요 변경 내용
- 실제 실행된 검증 결과
```

scope가 필요한 경우 `<prefix>(<scope>): <한글 제목>`을 사용합니다. 검증 근거가 없으면 검증 내용을 만들어내지 않습니다.

## 변경이 없는 경우와 금지 사항

staged, unstaged, 관련 untracked 변경이 없으면 커밋할 변경이 없다고 보고하고 메시지를 생성하지 않습니다. `git add`, commit, push, PR 생성과 파일 수정은 수행하지 않습니다.
