# Steps Documentation

## 핵심 원칙

완료된 사실만 기록합니다. Plans 문서가 없어도 작성하며, 코드, 설정, 테스트 결과, Git diff를 문서나 기억보다 우선합니다.

## 작성 전 확인

1. 적용되는 저장소 지침을 확인합니다.
2. 실제 변경 파일과 diff를 확인하고, 무관한 사용자 변경과 문서화 대상을 구분합니다.
3. 실행 로그나 현재 작업 기록에서 실행된 검증 명령과 결과를 확인합니다. 테스트 파일이나 CI 설정의 존재만으로 검증이 실행됐다고 판단하지 않습니다.
4. 관련 Plan이 있으면 실제 결과와 비교합니다.

확인할 수 없는 수행 순서, 문제, 의사결정이나 선택 이유를 사후에 만들어내지 않습니다. 추론이 필요한 내용은 확인 사실과 구분합니다. Steps는 시간순 재현보다 확인 가능한 결과와 근거를 중심으로 작성합니다.

## 문서 위치와 언어

위치와 이름은 다음 순서로 결정합니다.

1. 저장소 지침에 명시된 규칙
2. 저장소에서 이미 사용하는 문서 구조와 이름 규칙
3. 규칙이 없으면 `docs/steps/`

다른 문서와 번호나 파일명을 강제로 맞추지 않습니다. 문서 언어는 사용자 요청을 우선하고, 요청이 없으면 저장소의 기존 문서 언어를 따릅니다.

사용자가 파일 작성을 요청했을 때만 저장소에 문서를 생성하거나 수정합니다. 내용 작성만 요청한 경우에는 응답으로 제공합니다.

## 문서 내용

다음을 작업 규모에 맞게 작성합니다.

- 작업 목적과 변경 전 문제
- 확인한 구조와 근거
- 실제 적용 내용과 선택 이유
- 주요 변경 파일과 역할
- 변경된 계약, 데이터 또는 실행 흐름
- 실행한 검증과 결과
- 실행하지 못한 검증과 이유
- 남은 제한과 후속 작업

관련 Plan이 있을 때만 계획과 달라진 내용과 이유를 추가합니다. 관련 Commit 또는 PR 자료도 존재하고 현재 작업과 관련될 때만 연결합니다.

## 금지 사항

실행하지 않은 테스트를 통과했다고 쓰거나, 계획만 있는 기능을 완료로 기록하거나, Plans 내용을 반복하지 않습니다. `git add`, commit, push, PR 생성은 수행하지 않으며 커밋 메시지도 생성하지 않습니다.
