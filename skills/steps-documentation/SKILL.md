# Steps Documentation

실제 diff·코드·실행 기록과 관측을 확인한다. Plan·Context는 배경 자료이며 완료 사실의 증거를 대신하지 않는다. 사용자 변경과 기록 대상을 구분하고 수행하지 않은 검증·확인하지 않은 이유나 의사결정을 사후 창작하지 않는다.

작업 규모에 맞게 배경·실제 문제, 무엇을 왜 변경했는지, 전후 구조나 주요 lifecycle 흐름, 실행한 검증과 결과, 미실행 항목·제한·남은 사항을 설명한다. 관련 Plan과 실제 결과가 달랐다면 그 차이와 확인된 이유를 적는다. 단순 파일 나열이나 시간순 명령 일지, Plan 복사를 피한다. 비교 표나 Mermaid가 이해를 돕는 경우만 사용한다. 작은 변경이면 짧게 쓴다.

문서 파일 위치는 사용자 지정 → 저장소 관례 → `docs/steps/` 순서로 정한다. 사용자가 내용만 요청했다면 응답으로 제공한다. Context에 중요한 지속 결정이 있다면 필요한 연결을 남기고 완료된 Context는 동결한다. Steps 작성은 Git 실행 권한이 아니다.
