# Context lifecycle

Context는 명령 일지나 읽은 파일 목록이 아니라, 다음 세션의 판단에 필요한 지식이다. 사용자 지정 위치와 저장소 관례를 우선하고 없으면 `docs/context/<task-slug>.md`를 사용한다. 같은 작업의 기존 파일을 갱신한다.

요구, 확인한 구조·lifecycle, 중요한 관측과 근거·조건, 영향 범위, 결정, 남은 선택·미확정, 폐기한 주요 대안의 이유, 다음 작업과 재확인할 상태를 간결히 남긴다. 코드에서 즉시 확인 가능한 긴 내용은 복사하지 않는다. 사실과 가정·미확인을 구분한다.

중요한 사실이나 결정이 바뀔 때 현재 작업자가 갱신한다. Plan은 미래 작업, Steps는 실제 결과를 기록하므로 Context를 복사해 완료 사실로 바꾸지 않는다. 완료·취소 시 지속 결정은 Steps나 관련 문서에 연결하고 상태와 재개 조건을 남긴 채 동결한다. 자동 삭제하지 않는다.

새 세션은 Context로 맥락을 복구한 뒤 branch·관련 코드·환경·증거의 현재 유효성을 확인하고 달라진 부분만 조사한다. 읽기 전용 요청이면 파일 쓰기 대신 응답으로 인계한다.
