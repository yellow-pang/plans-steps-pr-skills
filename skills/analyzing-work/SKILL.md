# Analyzing Work

요구와 적용 지침, 현재 코드·설정·테스트·runtime·Git 상태를 확인한다. 기존 Context는 출발점이지 현재 사실의 대체물이 아니다. 분석만 요청받았다면 확인된 사실, 근거, 영향 종료 이유와 미확정 사항을 보고하고 코드 수정으로 확대하지 않는다.

관련 변경이 데이터·상태·API·DB·worker·async·Browser/provider·UI 경계를 통과하면 producer, 변환, consumer와 오류·상태 전이를 추적한다. 영향이 닫힌 근거가 있으면 조사를 마친다. 작은 국소 변경마다 저장소 전체를 조사하지 않는다. 실제 관측이 가능한 외부 값은 관측하고 의미·안정성을 판단한 뒤 계약으로 삼는다. 조회하지 못한 값이나 합성 fixture는 실제 동작으로 단정하지 않는다.

결과는 현재 참인 것(Analysis)과 앞으로 할 변경(Plan)을 구별한다. 원인·영향·근거와 남은 확인 방법을 다음 역할에 전달한다. 사용자가 구현까지 요청했고 필요한 선택이 해결됐다면 분석 응답만으로 작업을 끝내지 않는다.

긴 조사, 여러 경계나 세션을 거치는 작업, 명시적 인계 요청에는 [Context lifecycle](references/context-lifecycle.md)을 읽고 중요한 판단만 기록한다. 작은 작업에는 Context 파일을 만들 필요가 없다.
