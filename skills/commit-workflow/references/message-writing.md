# 커밋 메시지와 변경 범위

## 최근 대화보다 현재 대상

선택된 커밋 대상의 실제 diff와 관련 새 파일을 모두 확인한다. 출력이 잘렸다면 남은 내용을 읽는다. 제목이 앞선 변경 하나만 설명한다면 현재 전체 목적에 맞게 다시 쓴다. 이미 본문을 제안했어도 이후 변경이 추가됐으면 재대조한다. 대상 밖 변경까지 포함한 것처럼 쓰지는 않는다.

파일을 하나씩 나열할 필요는 없다. 각 중요한 변경 목적과 동작이 제목 또는 본문으로 설명돼야 한다. 하나의 기능에 속한 코드·테스트·문서는 한 단위로 묶을 수 있다. 서로 독립된 목적은 포함 범위와 분리 이유를 제시하되 사용자가 정확히 지정한 단위를 형식 때문에 거부하지 않는다.

## 언어와 제목·본문

기본 형식은 `<type>: <한국어 제목>`이며 저장소의 유형·scope 관례를 따른다. 일반적인 유형은 `feat`, `fix`, `refactor`, `docs`, `test`, `chore`다. 유형의 영어 표기와 코드 식별자는 한국어 본문과 양립한다.

“제목과 내용 보여줘”라면 제목, 실제 빈 줄, 본문을 제공한다. 본문은 주요 변화·이유·필요한 검증을 다루며 앞선 대화 순서를 재현하지 않는다. 계획 중인 기능이나 미실행 검증을 완료로 쓰지 않는다.

예시 형식이며 실제 내용은 현재 diff에서 작성한다:

```text
fix: 재시도 요청의 중복 작업 생성을 방지

- 동일 요청 식별자에 기존 작업을 반환하도록 저장 처리를 변경
- 재요청 시 화면이 기존 작업의 진행 상태를 표시하도록 연결
- 동시 재요청에서 작업이 중복 저장되지 않는지 확인
```

## 줄바꿈과 확인

표시할 본문은 실제 줄바꿈으로 작성한다. 문자열 `\n`이나 PowerShell의 개행 표기를 이스케이프하지 않은 텍스트로 삽입하지 않는다. EXECUTE에서는 UTF-8 메시지 파일과 `git commit --file <path>`처럼 셸 재해석을 피하는 전달 방식을 사용한다. 실제 저장된 제목·본문도 조회한다. 소스 코드를 설명하기 위해 의도적으로 쓴 `\n`까지 오류로 판정하지 않는다.
