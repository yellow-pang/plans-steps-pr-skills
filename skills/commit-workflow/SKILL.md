# Commit Workflow

먼저 요청의 완료 지점을 구별한다. **PREPARE**는 메시지·커밋 단위·push 대상 정보만 제공하며 staging·commit·push·PR을 실행하지 않는다. **EXECUTE**는 사용자가 명시한 commit 또는 push만 현재 권한과 지정 범위에서 수행한다. Commit 요청은 push나 PR을 포함하지 않고, push 요청은 미커밋 변경의 commit을 포함하지 않는다.

적용 지침·커밋 관례와 `git status`를 확인하고 staged(커밋에 포함하도록 선택한 변경), unstaged(아직 선택하지 않은 변경), untracked(새 파일)를 분리한다. 비밀정보 가능 경로는 내용 출력 전에 선별한다. staged가 있으면 기본 대상은 staged diff이며, 사용자가 다른 범위를 명시하면 그 범위를 따른다. 같은 파일의 제외된 수정 부분을 섞지 않는다. staged가 없으면 요청과 작업 근거에 맞는 변경만 후보로 삼고 관련 새 파일은 안전하게 확인한다. 변경이 없으면 메시지를 만들지 않는다.

메시지 작성 직전에 대상 전체의 실제 diff와 새 파일을 다시 확인한다. 이전 응답·마지막 수정·파일명 목록만으로 범위를 정하지 않는다. 서로 독립적으로 되돌릴 목적이면 분리를 제안하고, 하나의 목적에 속한 코드·테스트·문서는 함께 설명한다. PREPARE에서는 포함·제외 범위를 분명히 보고한다.

제목과 본문은 별도 언어 지시가 없으면 **한국어**로 쓴다. 저장소의 명시적인 언어 지침이 있으면 따르되 영어 커밋 이력만으로 한국어 기본값을 버리지 않는다. 유형 접두사와 코드 식별자는 원래 표기를 유지한다. “제목과 내용/본문” 요청이면 둘 다 제공한다. 일반 메시지 요청도 여러 변경이 있으면 주요 목적을 빠짐없이 설명하는 본문을 함께 제공한다. 한 줄 요청이나 한 줄로 충분한 단일 변경에서는 짧게 쓸 수 있다. 검증은 실제 근거가 있는 결과만 쓴다. 상세 형식·변경 누락 확인은 [메시지 작성](references/message-writing.md)을 필요한 때 읽는다.

EXECUTE 전에 [실행과 복구](references/execution.md)를 읽는다. 성공은 실제 커밋의 식별자·포함 범위·저장된 메시지 또는 push 대상 상태로 확인한다. 본문의 줄바꿈은 실제 개행으로 전달하며 문자열 `\n`으로 대체하지 않는다. 응답 유실 시 먼저 상태를 조회하고 중복 실행하지 않는다. force push·reset·history rewrite는 일반 요청 범위에 포함되지 않는다.
