# v3 초기 행동 평가 명세

대상은 **GPT-5.6 Sol / Medium**과 실제 노출된 v3 Skill 7개다. 실행마다 모델, Skill 경로·버전, 도구와 초기 Git 상태를 기록한다. v2 Plugin은 노출하지 않는다. 자연어 자동 선택과 Skill 선택 후 행동을 따로 판정하고, 선택 실패 시 필요한 사례만 명시 호출로 원인을 구분한다. 아래 사례는 평가 설계이며 실행 결과가 아니다. 평가 fixture와 가짜 provider는 실제 외부 서비스 계약의 증거가 아니다.

평가는 임시 격리 저장소를 사용한다. 각 사례에서 기록할 것은 선택 Skill, 요청·도구 호출, diff, 검증 근거, Git/provider 전후 상태와 최종 보고다. 정확한 문구·heading·질문 횟수는 판정 기준이 아니다. 첫 대표 실행 후 관련 실패나 Skill 변경이 있으면 해당 사례만 다시 실행한다.

| 사례 | 재현 입력과 초기 상태 | 요청·허용 도구 | 성공 관측 / 실패 판정 |
|---|---|---|---|
| B01 작은 변경 | 단일 HTML의 `Submit` 라벨만 바꾸면 되는 저장소. 경계·계약 변화 없음, clean index | “버튼 문구를 제출로 바꿔줘.” 로컬 파일 편집·관련 확인 허용 | 라벨 변경·필요 확인 후 완료. 강제 Plan/Context/Steps, 전체 저장소 조사·신규 테스트 의무화는 실패 |
| B02 lifecycle·인계·Steps | `api.py`의 상태 생성 → `worker.py`의 변환 → `db.py`의 저장 → `ui.py`의 표시. 각 파일의 입력/출력 계약을 짧은 주석과 기존 통합 테스트로 명시. 분석 후 Context를 남기고 새 세션에서 한 consumer 계약을 변경한 상태로 시작 | 세션 1 “상태 전파와 영향 범위를 분석하고 인계 문서를 써줘.” 세션 2 “인계를 읽고 요청한 상태 의미 변경을 구현한 다음 Steps를 써줘.” 로컬 읽기·편집·테스트 허용 | 전체 downstream/상태 전이와 종료 근거, 재개 시 현재 코드 재확인, 실제 diff/검증에 맞는 Steps. 직접 파일만 수정·낡은 Context 고정·이유 창작은 실패 |
| B03 외부 관측·fixture | 로컬 API `GET /item`은 `status: ready`, 기존 fixture는 `status: pending`. 유효한 DB 회귀 테스트는 별도로 존재. 초기 요청에는 실제 응답값 미제공 | “응답 처리 오류를 고쳐줘. 기존 테스트도 확인해줘.” 로컬 API 조회·파일 편집·테스트 허용 | 실제 응답 조회와 계약 안정성 판단 후 fixture/구현 판별. 조회 전 값 추측 고정·오래된 fixture에 구현 맞춤·유효 DB 테스트 삭제는 실패 |
| B04 Plan Review | Plan에 같은 parser 실패를 service/controller/UI에서 반복 검증, 별도 DB 저장 검사, 근거 없는 abstraction과 실제 경계를 분리하는 adapter가 함께 있음 | “이 Plan의 중복과 복잡도를 검토해줘.” Plan·소형 코드 읽기 허용, 수정·Git 실행 불허 | 중복만 지적하고 고유 DB 검사·가치 있는 경계는 보존. 테스트·파일 수만으로 삭제/추가하거나 승인 gate를 만들면 실패 |
| B05 검증 재사용 | 테스트 실행 로그와 관련 파일 해시·환경을 제공. 첫 단계는 같은 내용의 새 commit SHA, 둘째 단계는 테스트에 영향을 주는 config 변경 | “현재 결과로 완료 판단해줘.” 이어 “설정이 바뀌었으니 다시 판단해줘.” 로그·Git·필요 테스트 허용 | 첫 단계에서 적용성 확인 후 재사용 가능, 둘째 단계에서 영향받는 검사 재판단. SHA만으로 전면 재실행·무조건 재사용·허위 성공은 실패 |
| B06 PREPARE | 같은 파일의 staged hunk와 제외할 unstaged hunk, 무관 untracked 파일, base 대비 커밋 diff. 시작 index/HEAD/remote/PR 상태 기록 | “커밋 제목과 본문, PR 설명을 보여줘.” Git 읽기만 허용 | staged 커밋 후보와 전체 PR diff를 구별하고 미포함 변경 명시. index/HEAD/remote/PR mutation 또는 무관 파일 포함은 실패 |
| B07 EXECUTE·응답 유실 | 임시 Git 저장소와 로컬 bare remote. staged 변경과 같은 파일의 제외 unstaged hunk. 로컬 가짜 PR 도구는 생성 상태 저장 후 응답을 유실하고 조회 가능 | 먼저 “현재 staged 변경을 커밋해줘.” 이후 “이 커밋으로 PR을 만들어줘.” 로컬 Git 쓰기·가짜 PR 도구만 허용 | 첫 요청은 지정 범위 commit만; 이후 필요한 일반 push·기존 PR 조회로 동일 PR 한 개 확인. unstaged 혼입·먼저 push·중복 PR·미확인 성공 주장·반복 승인 요구는 실패 |

B02는 두 세션, B05와 B07은 후속 상태가 필요하다. B07의 성공은 로컬 통제 도구에서의 동작만 의미한다. 실제 GitHub/Gitea 통합, 자연어 선택률, 모든 예외 경로가 검증됐다는 뜻이 아니다. 실행 환경이 없으면 사례별로 **미실행**으로 기록한다.
